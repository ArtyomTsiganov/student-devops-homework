# Материалы второй пары по Docker

Здесь собраны примеры с пары и домашнее задание. Вы посмотрите слои образов, проверите, где контейнеры хранят данные, и запустите приложение через Docker Compose.

## Что понадобится

- Docker Engine на Linux или Docker Desktop в режиме Linux-контейнеров.
- Docker Compose с поддержкой `up --wait` и `develop.watch`.
- dive, Bash, curl, jq, tar и стандартные утилиты Unix. На Windows работайте в WSL 2.
- Доступ к Docker Hub, PyPI и пакетам Debian, несколько гигабайт свободного места.

## С чего начать

Распакуйте материалы и откройте терминал в папке `student-pack`. Проходите темы по порядку:

1. [01-dive](01-dive/): сравните слои и три варианта сборки. - есть
2. [02-storage](02-storage/README.md): проверьте, какие данные сохраняются после удаления контейнера, и восстановите том из копии. - есть
3. [03-compose](03-compose/README.md): запустите Flask, Nginx, PostgreSQL и Redis.
4. [HOMEWORK.md](HOMEWORK.md): выполните домашнее задание.

В начале темы перейдите в её папку командой из README. Дальше выполняйте команды по порядку в том же терминале. В конце выполните раздел «Убрать за собой» и вернитесь назад: `cd ..`. Перед повторным прохождением тоже выполните очистку.

Вывод команд может отличаться от примеров: размеры, ID, IP-адреса и версии зависят от вашей системы.

## Перед запуском

Убедитесь, что имена `student-dive`, `student-st-*`, `student-compose` и порты `18090` и `18091` свободны. Если запускаете второй экземпляр, замените имена во всех командах и настройках.

В теме про хранение данных есть шаг с `sudo` и `nsenter`. Он рассчитан на Linux с containerd image store. В Docker Desktop его можно пропустить: эти файлы находятся внутри служебной виртуальной машины.

Пароли из `.env.example`, Flask debug и Redis без пароля подходят только для локального упражнения.

Команды очистки удаляют ресурсы конкретной темы. Скачанные базовые образы останутся. Общая очистка Docker не нужна. Перед удалением тома проверьте, что в нём только учебные данные.
